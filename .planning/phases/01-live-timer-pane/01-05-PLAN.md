<objective>
Add the write path to the skeleton (CTRL-01): a one-click "Stop timer" that stops only the displayed timer through `api.time.stop`. The write goes through one serial write queue, the button shows a busy state, a "no active session" race stays silent, and any other failure shows a Notice.

Purpose: this proves the write half of the walking skeleton and keeps the user's tracked time safe. Every write goes through TaskNotes' lock and field mapping, carries a mutation context, and is serialized through one queue that Phase 2's start and switch will reuse. The pane writes only when the user clicks (D-05). Completion auto-stop stays TaskNotes' own, and it also covers the user's archive flow (a completed-type status). The archive auto-stop planned earlier (D-06..D-11) was superseded on 2026-10-13 and is not built.
Output: `WriteQueue`, `TimerController`, `errors.ts`, and the bridge write facade. The view gets the Stop button. New test file: `tests/controller.test.ts`.
</objective>

## Phase Goal

**As a** TaskNotes user, **I want to** see and stop my running timer from a sidebar pane, **so that** I always know what I am timing and for how long.
